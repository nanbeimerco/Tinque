# v2.6.0 実装計画書（原案）：ホームの充実・ヒート表示の拡張

作成日: 2026-11-10 / 対象: v2.5.1 の次

> **v2.6.0 で実装済み（11/10）**：ミックス（案A・押すとすぐシャッフル）、ヒート棚（曲／アルバム／アーティスト／プレイリスト、★お気に入りを含む）、急上昇、去年の今ごろ、アルバムの聴き残し、時間帯の定番、ストリーク、ライブラリの活用度、HomeModel、プレイリストから再生した記録（PlaySource）、曲ごとの時間帯の記録、赤橙 12°、共通の時計（再生中だけ流れる／プレイヤーを上げている間はページ側を止める）、タイルの縁取り（E1＋波、0 から表示、アートを 6.5dp 内側へ。ヒートをオフにすると元の大きさ）。未実施：ミックスの長押しで一覧を開く機能、gfxinfo による計測。

## 0. 方針

ホームの役割は「手持ちのライブラリから、今聴きたい曲と忘れていた曲を見つけてもらうこと」。
ライブラリは「自分で選んだもの」、ホームは「アプリが気づいたもの」という分け方は v2.5 のまま。

今回の柱は4つ。

1. **アプリが考えるミックス**：ワンタップで再生できるおまかせの再生リスト
2. **ヒート棚の拡張**：「ヘビロテ」を「ヒート」にして、曲・アルバム・アーティストを並べる
3. **新しい棚**：急上昇、去年の今ごろ、アルバムの聴き残し、時間帯、ストリーク、ライブラリの活用度
4. **ヒート表示**：色を赤橙に変更、4.8以上の波をどこでも動かす、タイル表示に縁取りを付ける

## 1. 今あるデータで何ができるか（調査結果）

| データ | 中身 | 保存期間 | 使える案 |
|---|---|---|---|
| `HeatStore`（heat.json） | 曲ごとの短期スコア（半減期7日）・長期スコア（半減期30日）、再生数、完走数、スキップ数、最初と最後の再生日、直近7日の再生日、**週ごとのレベル（直近8週）** | 曲ごとに無期限 | ヒート棚、急上昇、アルバムの聴き残し |
| `ListeningStats`（月ごとのファイル） | **月ごと**の曲・アルバム・アーティスト別の再生時間と回数、**日ごと**の再生時間、**時間帯（24時間）ごと**の再生時間 | **36か月**（1か月あたり曲600件まで） | 去年の今ごろ、ストリーク、活用度 |
| `LocalPlayStatsStore` | 曲ごとの再生回数と最終再生日時 | 無期限 | 活用度、まだ聴いていない曲 |

足りないデータは次のとおり。

- **曲ごとの時間帯がない。** 時間帯は月の合計しかなく、「朝によく聴く曲」は今のデータからは出せない。曲ごとに4つの時間帯（朝・昼・夕方・夜）の再生回数を数え始める必要がある（→ 3-5）。
- **「去年の今ごろ」は、記録を始めて1年たたないと出ない。** 月ごとの記録は残っているので、1年分がないうちは「3か月前」「半年前」で代わりにする（→ 3-2）。

## 2. アプリが考えるミックス（クイックミックス）

ホームの上（ヘッダーのすぐ下）に、横に並ぶピル型のボタンを置く。押すとすぐにシャッフル再生が始まる。長押しすると中身の一覧を開き、そこから順番に再生もできる。

### 2-1. ミックスの種類（名前は案。下に候補を並べた）

| 内部名 | 中身 | 条件 |
|---|---|---|
| `HOT_MIX` | ヒート4以上の曲 | 10曲以上あるとき表示 |
| `REDISCOVER_MIX` | 前はよく聴いていて、最近聴いていない曲（ピーク2.5以上、30日以上再生なし） | 10曲以上 |
| `NEW_MIX` | 30日以内に端末に追加された曲 | 5曲以上 |
| `DEEP_CUTS_MIX` | ヒートの高いアルバムにある、まだあまり聴いていない曲（3-3と同じ考え方） | 10曲以上 |
| `TIME_MIX` | 今の時間帯によく聴く曲（3-5のデータがたまってから） | 10曲以上 |
| `UNPLAYED_MIX` | 一度も再生していない曲 | 10曲以上 |

- 1つのミックスは最大50曲。そのままシャッフルせず、ヒートやアーティストが偏らないように並べる（同じアーティストを3曲続けない）。
- 中身は日付が変わるまで同じにする。開くたびに変わると「さっきの曲」をもう一度探せないため。

### 2-2. 名前の候補

| 内部名 | 案A（短く） | 案B（ことば） | 案C（英語） |
|---|---|---|---|
| HOT_MIX | ヒート | いま熱い曲 | Hot |
| REDISCOVER_MIX | 久しぶり | あの頃よく聴いた | Rewind |
| NEW_MIX | 新着 | 入ったばかり | Fresh |
| DEEP_CUTS_MIX | 聴き残し | アルバムの奥 | Deep Cuts |
| TIME_MIX | 朝の定番／夜の定番（時間帯で変わる） | いつもの朝／いつもの夜 | Morning / Night |
| UNPLAYED_MIX | 未再生 | まだ聴いてない | Unplayed |

絵文字は付けず、アイコン（Material Symbols）で区別する。私のおすすめは **案A**。ピルに収まりやすく、ホームの棚の名前とも揃えやすい。

## 3. ホームの新しい棚

### 3-1. 「ヒート」棚（今の「ヘビロテ」を置き換える）

- 名前を「ヘビロテ」から「**ヒート**」に変える。
- 棚の右上に `曲 / アルバム / アーティスト` の切り替えを付ける（`SegmentedButton` を小さくしたもの）。
  - アルバム・アーティストのヒートは、既存の `HeatStore.groupLevel()` で出す（収録曲のヒートをまとめた値）。
  - アルバムは正方形のカード、アーティストは丸いカード。ヒートはカードの縁取り（5-3）とカード下のメーターで見せる。
- 「今ハマっている曲」（ヒーロー）は残す。

### 3-2. 「去年の今ごろ」（タイムカプセル）

- 去年の同じ月に再生時間が長かった曲・アルバムを上から並べる。今もヒートが高い曲は外す（今聴いているものでは懐かしくないため）。
- 1年分の記録がない間は、さかのぼれる一番古い月で代わりにする：「3か月前によく聴いていた曲」「半年前によく聴いていた曲」。
- 記録が2か月分しかなければ、棚ごと出さない。
- 月ごとの記録の曲IDは `videoId` なので、端末内の曲との突き合わせに `videoId` の一覧を使う。

### 3-3. 「アルバムの聴き残し」（ディープカッツ）

- 条件：アルバムのヒート（`groupLevel`）が2.5以上で、そのアルバムの中で一度も再生していない曲、または再生数がアルバム平均の1/3以下の曲。
- カードには「〇〇（アルバム名）から」と出す。
- 1アルバムから最大2曲まで（同じアルバムの曲ばかり並ばないように）。

### 3-4. 「急上昇」（ネクスト・ブレイク）

- 短期スコアが長期スコアより大きく伸びている曲（`trend > 0`、短期/長期の比が大きい順）。レベルはまだ低めでもよい（1.5以上）。
- 「今ハマっている曲」と重なる曲は外す。
- `HeatInfo` に短期と長期の比を表す `momentum: Float` を足す（publish の中で計算するだけで、保存データは変わらない）。

### 3-5. 時間帯の棚（朝の定番・夜の定番）

- 新しいデータ：`HeatEntry` に `slots: IntArray(4)` を足し、朝（5〜11時）・昼（11〜17時）・夕方（17〜22時）・夜（22〜5時）の再生回数を数える。古い heat.json は空として読めるので、移行処理はいらない。
- 今の時間帯に、その曲の再生の40%以上が集まっていて、3回以上聴いた曲を並べる。
- データがたまるまで（目安で2〜3週間）は出さない。バックアップにもそのまま入る。

### 3-6. リスニング・ストリーク（ヘッダーのチップ）

- 「5日連続」「今週 8時間45分」。今あるヘッダーのチップ（今日・今週）の隣に足す。
- 1日の判定：その日の再生時間が5分以上。日ごとの記録（`ListeningStats` の days）から計算できる。
- 2日以上続いたときだけ出す。途切れても何も言わない（せかす表示はしない）。

### 3-7. ライブラリの活用度（インサイトカード）

- 「この3か月で、ライブラリの42%を再生しました」。
- カードを押すと「3か月以上再生していない曲」の一覧を開く。その一覧からシャッフル再生できる（= UNPLAYED_MIX の仲間）。
- 計算は `LocalPlayStatsStore` の最終再生日時を使う。曲数が多いと重いので、IO スレッドで計算して結果をキャッシュする（次の項目）。

### 3-8. 計算のしくみ（共通）

今の `HomeScreen` は、画面の中で `LaunchedEffect` を使って計算している。棚が増えるのでこれを分ける。

- `feature/home/data/HomeModel.kt`（新規）：棚とミックスの中身を全部まとめて計算し、`StateFlow<HomeContent>` で出す。
- 計算し直すのは、曲一覧・ヒート・再生記録が変わったときと、日付・時間帯が変わったときだけ。ヒートは再生のたびに変わるので、計算し直しは最短でも数秒に1回にまとめる。
- 全部 `Dispatchers.Default`／`IO` で計算する。画面側は表示するだけにする（v2.5.1 のカクつきの教訓）。

### 3-9. 並び順の初期値（新しくインストールした人）

ヘッダー → ミックス → 今ハマっている曲 → ヒート → 急上昇 → 新着 → 最近再生した曲 → 去年の今ごろ → アルバムの聴き残し → 時間帯 → 久しぶりに聴く → まだ聴いていないアルバム → 活用度 → 今週の記録

- 更新した人は、今の並び順のうしろに新しい棚を足す（v2.5 の取り決めどおり、初期値は新しくインストールした人だけ）。
- 新しい棚も、ホームのレイアウト編集シートで並べ替えと非表示ができるようにする。

## 4. ヒートの色：橙から赤橙へ

- 今の橙は色相22°。赤橙として **12°前後** を提案する。モックで 8° / 12° / 16° を並べて決めたい。
- 選択肢の名前を「オレンジ」から「**赤橙**」に変える。中身（`HeatColor.ORANGE`）はそのまま使うので、橙を選んでいた人は自動で赤橙になる。
- アートワーク色が使えないときの代わりの色も、同じ赤橙にする。
- 赤に寄せると、レベルの低いうちの「灰色から色づく」途中が茶色っぽく見えやすい。明るさの式（今は 0.70 → 0.62）を少し上げる調整を、モックで一緒に確認する。

## 5. ヒートの表示を広げる

### 5-1. 4.8以上の波をどこでも動かす

今の状態は次のとおり。

| 場所 | 今 | v2.6.0 |
|---|---|---|
| プレイヤー | 動く | 動く |
| 長押しの詳細 | 動く | 動く |
| 曲リストの小さな印（30dp） | 止まっている | 動かす |
| アルバム・アーティストの見出し | 止まっている | 動かす |
| ホームのカード・ヒーロー | 止まっている（v2.5.1 で止めた） | 動かす |
| 設定のプレビュー | 止まっている | 動かす（5.0のサンプルとして） |

**難しいところ（正直に書く）**

1. **ホーム（ガラスの下）。** v2.5.1 のカクつきは、ホームの小さな動きのせいでガラス越しの画面全体が毎フレーム描き直されたことが原因だった。波を戻すと同じことが起きるおそれがある。
   - 対策：動く波が全部、**1つの共通の時計**を見るようにする（今は1本ずつ別のアニメーション）。さらに、プレイヤーの開閉中と、プレイヤーを全画面で開いている間は、その下の画面の波を止める（見えていないため）。
   - 対策の後で、v2.5.1 と同じ方法（`gfxinfo`）で測る。ホームからの開閉が 10ms 前後に収まらなければ、ホームだけ「波の更新を2フレームに1回」に落とす。
2. **再生を止めている間。** 今は再生中だけ画面の描画が続いている。波が動くと、止めていてもホームを開いている間はずっと描き続けることになり、電池に響く。
   - 提案：**再生中だけ動かす**（止めている間は止まった波）。「どこでも同じ」という条件は保てて、電池も守れる。
3. **曲リストの小さな印。** 幅30dpだと動きがほとんど見えない。動かすこと自体は軽い（共通の時計にすれば、1行ごとの負担はわずか）。見えにくいのは仕様として受け入れる。
4. **「動きを減らす」設定がオンのとき**は、今までどおりどこも動かさない。
5. **通知・ウィジェット**には波を出していないので、対象外。

### 5-2. 共通の時計（実装）

- `ui/components/HeatClock.kt`（新規）：動いている波が1本でも画面にあるときだけ時を刻む、`withFrameNanos` を使った共通の位相。
- 波は位相を **描画のときにだけ** 読む（v2.5.1 の方式を守る）。
- 止める条件（再生していない、プレイヤーの開閉中、動きを減らす）は時計の側でまとめて判断する。

### 5-3. グリッド・アルバムアートのタイルの縁取り

> **決定（11/10）：E1「伸びる線」**（mocks/heat_tile_v2.html）。線の長さ＝ヒート（5で一周）、上の真ん中から時計回り、残りは薄いトラック、両端は丸くすき間を空ける（M3 の進捗インジケーター風）。4.8 以上の動き方は mocks/heat_tile_v3.html の8案から選ぶ。以下の表は最初の原案。

アルバムやアーティストを正方形・丸で並べる場所（ライブラリのカード、ローカル音楽のアルバムグリッド、ホームのカード）に使う。

| レベル | 見た目 |
|---|---|
| 4未満 | 何もなし（今と同じ） |
| 4〜4.8 | ヒート色の縁取り（2dp）。レベルが上がるほど濃くなる |
| 4.8以上 | 縁取りが**グラデーション**になり、ゆっくり回る（波と同じ共通の時計で動く） |

- 縁取りの外側にぼかした光（グロー）を付ける案もあるが、ぼかしは重いので、最初は付けない。モックで「縁取りだけ」と「縁取り＋薄いグロー（ぼかさない放射状のグラデーション）」を比べて決める。
- 曲リストの1行は今のメーターの印のままにする（縁取りはタイルだけ）。

## 7. 気をつけること（今までの教訓）

- `SettingsScreen` は JVM のメソッドサイズの上限ぎりぎり。設定項目（色の名前変更など）を足すときは、別の関数に分ける。
- `NowPlayingScreen` に処理を足すと R8 の不具合で VerifyError が出ることがある。足すものは別の関数にする。
- Kotlin のコードを PowerShell の `"..."` 文字列で書き込まない（`${...}` が展開される）。
- ホームの画面の中で重い計算や、ずっと続くアニメーションを動かさない。

## 8. 決めてほしいこと

1. **ミックスの名前**：案A・B・C のどれにするか（混ぜてもよい）。
2. **赤橙**：12°前後でよいか。モックで3つを見比べて決めるか。
3. **再生を止めている間の波**：「再生中だけ動く」でよいか。
4. **タイルのグロー**：縁取りだけで始めるか、モックで比べるか。
5. **ミックスを押したとき**：すぐシャッフル再生（長押しで一覧）でよいか。逆（押すと一覧、再生ボタンで再生）がよいか。
6. **バージョン**：v2.6.0 として出すか、段階ごとに 2.5.x で出すか。
