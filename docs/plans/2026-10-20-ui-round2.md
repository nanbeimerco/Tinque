# UI調整 第2弾 実装計画書

作成日: 2026-10-20 / 対象: Tinque 2.3.7(`com.music.tinque`)

前回の実装(上部ボタンの Liquid Glass 化、フォルダの Expressive グループ化、EQ 全画面化、再生ボタン刷新、カスタムフォント)を実機で確認したうえでのフィードバックへの対応計画。

---

## 0. 新しいデザインルール

> **Liquid Glass は「動くコンテンツの真上」にだけ浮かべる。固定された帯(背景付きバー)の中には置かない。**

- ガラスは下を流れるコンテンツを屈折・ぼかしして初めて意味がある。不透明・半透明の帯の上に置くと、ガラスの下には「帯の単色」しかなく、光学的な表現が成立しない。
- したがって、上部の「帯」そのものをなくし、ボタンはコンテンツの上に直接浮かべる。
- 例外: ステータスバーの文字(時計・電池)の可読性のため、**ステータスバーの高さだけ**ごく弱いフェードを残す(エッジのない、ボタンの背後に回り込まないグラデーション)。

このルールは画面ごとではなく共通部品(`FrostedTopBar` と `TopFadeBlur`)で一括適用する。

## 1. 上部の帯を廃止し、タイトルとロゴの置き場所を決める

### 現状
- [FrostedTopBar.kt](../../app/src/main/java/com/music/bitchord/ui/components/FrostedTopBar.kt) は通常時に `background.copy(alpha = 0.92f)` の帯を敷き、その中央に小さいタイトル、左にロゴ/戻る、右に設定を置いている。
- その下に [TopFadeBlur.kt](../../app/src/main/java/com/music/bitchord/ui/components/TopFadeBlur.kt) が「バー高さ+ランプ」ぶんのぼかしを描いている。
- 前回ボタンをガラス化した結果、「帯の中のガラス」になっていて浮いている(特に設定画面)。

### 変更後のレイアウト

```
┌──────────────────────────────┐
│ 12:00            (弱いフェード)  │ ← ステータスバーの高さだけ
│ (←)        [ ライブラリ ]      (⚙) │ ← 浮いたガラス。中央のカプセルはスクロール後だけ出る
│                              │
│ ライブラリ                      │ ← 大見出し(コンテンツの一部としてスクロールする)
│ [すべて][お気に入り][プレイリスト]  │
│ ┌──────────────────────────┐ │
│ │ ...                        │ │
```

1. **帯を削除**: `FrostedTopBar` の背景塗りを全モードで透明にする。区切り線(divider)も削除。
2. **ボタン**: 戻る・設定・並べ替えは今の `TopBarGlassButton` をそのまま使い、コンテンツの上に浮かべる。
3. **ページ名(「設定」「ライブラリ」など)**:
   - 静止時: 各ページの先頭に**大見出し**(`headlineLarge` 相当、左寄せ)をコンテンツとして置く。スクロールで一緒に流れる。
   - スクロール後: 大見出しが隠れたら、ボタンの間に**小さなガラスのカプセル**でページ名を表示する(フェードイン)。カプセル自体もコンテンツの上に浮かぶガラスなので、ルールと矛盾しない。
   - 既存コードには「大見出しが静止時のタイトルを担い、スクロールで小タイトルが出る」(Apple Music 方式)の仕組みが `alwaysShowTitle` / `scrolled` として既にあるので、それを流用する。
4. **左上のロゴ**: 帯から外し、ホームの大見出しの位置(コンテンツ先頭)に移す。ほかのタブでは表示しない。戻るボタンがない画面の左上は空ける。
5. **`TopFadeBlur`**: 高さを「ステータスバーの高さ+16dp 程度」に縮める。ボタンの背後にはかからないので、ガラスは素のコンテンツをサンプリングできる。「ぼかしを減らす」設定時は、同じ高さの単色グラデーションにする。
6. **影響範囲**: ホーム/各タブ/設定/Replay/ YouTube Music の詳細ページ。各ページの先頭パディングは `topBarContentPadding()` 経由なので一括で調整できる。大見出しのない画面には、大見出しを足す必要がある(設定・Replay・各タブ)。

### 要確認(実装前に決めたいこと)
- A. スクロール後のタイトルカプセルを出すか(推奨: 出す)。
- B. ロゴをホームの大見出し位置に移すか、完全に削除するか(推奨: ホームの見出し位置に移す)。

## 2. クワイエットモード時の上余白

### 原因
クワイエットモード(と「ステータスバーを表示」オフ)ではステータスバーを `hide()` するため、`WindowInsets.statusBars` が 0 になる。`topBarHeight()` は `statusBars + 52dp` なので、ボタンが画面の上端から約 5dp の位置まで上がってしまう。パンチホールカメラにも近くなる。

### 対応
- 上部インセットを「`statusBars` と `displayCutout` の大きい方。ただし最低 16dp」に変える。
- `topBarHeight()` / `topBarContentPadding()` を1か所直せば、ボタン・ページ先頭・フェードがまとめて揃う。
- `WindowInsets.statusBarsIgnoringVisibility` を使い、隠していても本来の高さを確保する案もある。ただし、隠したのに空白が残る見た目になるため、上の案を推奨。

## 4. ライブラリ「すべて」表示のセクション化

### 現状
- [LibraryScreen.kt](../../app/src/main/java/com/music/bitchord/feature/library/ui/LibraryScreen.kt) の「すべて」は、お気に入り1行+プレイリストのカードを並べるだけ。
- 「最近再生した曲」「よく再生する曲」はフィルターを切り替えたときだけ表示される。

### 変更後(「すべて」選択時)
フォルダ画面と同じ Expressive グループ(大きな角丸コンテナ+細い区切り)で4セクションに分ける。

1. **お気に入り** — 1行(ハートのアートワーク、曲数、再生ボタン)。タップで今のお気に入り一覧へ。
2. **プレイリスト** — 見出しの右に「＋ 新規作成」。各プレイリストを1行(カバー、名前、曲数、⋮メニュー)で並べる。
3. **最近再生した曲** — 上位5曲を `SongRow` で表示し、見出しの右に「すべて表示」(今の履歴画面へ)。
4. **よく再生する曲** — 上位5曲。サブテキストに再生回数を出す。「すべて表示」付き。

- 0件のセクションは非表示にする。プレイリストが0件なら「新規作成」行だけ出す。
- 「お気に入り」「プレイリスト」などのフィルターを選んだときは、従来どおりそのセクションだけを表示する。
- **グリッド/リスト切替**: 「すべて」は常にセクション表示にし、グリッド切替はフィルター「プレイリスト」のときだけ有効にする(要確認 C)。
- 右端の高速スクロール(FastScroller)は、行の位置対応が崩れるため「すべて」では非表示にする。
- 共通部品 `ExpressiveGroup` / `expressiveItem`(前回追加)を使い、新規の見た目部品は増やさない。

### フィルター列(すべて / お気に入り / プレイリスト / 最近再生 / よく再生)の扱い

現状: [LibraryHeaderBar.kt](../../app/src/main/java/com/music/bitchord/feature/library/ui/components/LibraryHeaderBar.kt) のチップ列と右端の「＋」は、一覧の上に**固定**されている(スクロールしない)。上部の帯と合わせて、実質的に2段目の帯になっている。帯を廃止するなら、これも固定をやめる必要がある。

- **案1(推奨) — 見出しと一緒にスクロール**: 大見出し「ライブラリ」のすぐ下にチップ列を置き、コンテンツの一部としてスクロールさせる。
  - 「すべて」が4セクションになり、各セクションに「すべて表示」が付くので、チップを押す必要がある場面自体が減る。
  - ボトムバーのライブラリタブを再タップすると、先頭へスクロールして「すべて」に戻る(7章の「トップへ戻る」と同じ操作)。チップへはいつでも1タップで戻れる。
- **案2 — チップ列を浮かぶガラスにする**: チップ列全体をガラスのカプセルにして、スクロール後もボタンの下に浮かせ続ける。ルール上は問題ない(ガラスが動くコンテンツの上に浮いている)。ただし、上部にガラスが2段並び、一覧の見える範囲が狭くなる。
- **案3 — タイトルカプセルから切り替え**: スクロール後に出るタイトルカプセル(1章)をタップすると、フィルターのメニューが開く。案1との併用も可。

どの案でも共通で行うこと:
- チップの見た目を EQ と同じ Expressive のピル型(選択中は塗りつぶし)に揃える。
- 右端の「＋(新規プレイリスト)」はチップ列から外し、「プレイリスト」セクション見出しの「＋ 新規作成」に移す。
- グリッド/リスト切替は、フィルター「プレイリスト」のときだけ見出し横に出す。

### 要確認
- C. 「すべて」でグリッド表示を選んでいるユーザーへの扱い(推奨: 「すべて」は常にセクション表示)。
- F. フィルター列の置き方(推奨: 案1。必要なら案3を併用)。
- D. 最近/よく再生のプレビュー件数(推奨: 5曲)。

## 5. イコライザー画面の左右上ボタンを Liquid Glass に

### 現状と課題
EQ は全画面の `Dialog` で、アプリ本体とは別のウィンドウになっている。本体のガラス用背景(`LocalAppBackdrop`)は EQ の中身を記録していないため、そのままガラスにしてもサンプリングする対象がない。

### 対応
- EQ 内で専用の背景レイヤー(`rememberLayerBackdrop`)を作り、スクロールするコンテンツ側に `layerBackdrop` を付けて記録する。そのうえで、EQ 内だけ `LocalAppBackdrop` をこれに差し替える。
- 上部の戻る・リセットボタンは、コンテンツの上に重ねた(`Box` で重ねる)`TopBarGlassButton` にする。帯は置かない(ルール0)。
- 「イコライザー」の大見出しはスクロールするコンテンツ側に残す。スクロール後は、1章と同じタイトルカプセルを出す。
- ステータスバー部分は1章と同じ弱いフェード。上余白は2章と同じ計算を使う。

## 6. ライブラリ→フォルダ遷移時の処理落ち

### 推定原因(確度の高い順)
1. **フォルダツリーの再構築がメインスレッドで毎回走る**: `FolderBrowserScreen` は `remember(songs, customRootPath) { FolderTreeBuilder.build(...) }` で、全曲のパス分割と、全フォルダの自然順ソートを合成中に実行している。タブを離れると画面ごと破棄されるため、フォルダタブに入るたびに作り直している。
2. **前回のデザイン変更による初回描画の増加**: サムネイルを 52→64dp に拡大(画像のデコード量が増加)。行ごとの `clip` はグラフィックスレイヤーを作る。
3. ルート直下に曲が多い場合の `SongRow`(スワイプ処理付き)の初回生成。

### 進め方
1. **計測が先**: デバッグビルドでツリー構築の時間をログ出力し、`adb shell dumpsys gfxinfo com.music.tinque framestats` で切替時のジャンクフレームを取る。原因1が主因かどうかを数字で確認する。
2. **対策(原因1)**: ツリーを画面の外で保持するキャッシュ(曲リストとルートパスが同じなら再利用)にし、構築は `Dispatchers.Default` で行う。初回だけ短いスケルトン表示を出す。
3. **対策(原因2)**: 計測で効いていれば、行の `clip` を `background(shape)` と境界付きリップルに置き換える。サムネイルのデコードサイズも表示サイズに固定する。
4. 前回のフォルダデザインは維持したまま直す方針。

## 7. ライブラリ→他タブ→ライブラリで初期画面に戻る問題

### 原因
- `MainActivity` の `AnimatedContent` はタブごとに中身を作り直すため、タブを離れると `LibraryScreen` が破棄される。
- ドリルダウン状態(`drillDownLabel` / `drillDownPlaylistId` など)は `remember` なので消える。フィルターは `rememberSaveable` だが、`SaveableStateHolder` で包まれていないため、これも保存されない。

### 対応
1. **`MainActivity` に `rememberSaveableStateHolder()` を導入**し、各タブの中身を `SaveableStateProvider(key)` で包む。これで全タブの `rememberSaveable` とスクロール位置(`rememberLazyListState` は保存対応済み)が、タブ切替後も復元される。
2. **ライブラリのドリルダウン状態を保存可能にする**: 「お気に入り」か「プレイリストID」かを `rememberSaveable` で持つ。曲リストは保存せず、復帰時に `LocalFavoritesStore` / `LocalPlaylistStore` から引き直す(大きなリストを保存しないため、プロセス復帰にも強い)。
3. 戻るボタンの登録(`onCollectionNavigationChanged`)は、復帰時の `LaunchedEffect(inDrillDown)` で再登録されることを確認する。
4. **ボトムバーで表示中のライブラリタブをもう一度タップしたら、ライブラリのトップへ戻る**。アルバム/アーティスト/フォルダと同じ挙動に揃える。
5. フォルダタブが独自に持っているグローバルマップ(`PersistedFolderPathStacks`)は、今回は触らない(動作中のため)。

## 8. アルバム/曲入りフォルダを開いたあと、ワンテンポ置いてぼかしが強くなる

### 原因
[DrillDownSongList.kt](../../app/src/main/java/com/music/bitchord/feature/localmusic/ui/components/DrillDownSongList.kt) の `CollectionPageBackground` は、全画面アートを次の2段階で描いている。

1. **開いた直後**: くっきりしたアートの下部に、アート色のグラデーション(wash)を重ねるだけ。
2. **280ms 後**: アートの下半分(高さ35%から75%にかけて徐々に)に **48dp ぼかしたコピー** を 280ms かけてフェードインさせる(「soft foot」処理)。

遅らせている理由は、スライドイン中に重いぼかしを走らせないため(コード内コメントより)。ユーザーが「ぼかしが強くなる」と感じているのは、2段目のこの処理。

### 対応(推奨: 案1)
- **案1 — 2段目を廃止**: ぼかしたコピーを描かず、開いた直後の見た目(くっきりしたアート+wash)を最終形にする。後からの変化がなくなる。オフスクリーン合成の48dpぼかしも不要になり、アルバムを開くときの負荷も下がる(6章の処理落ち対策にも効く)。
- **案2 — ごく弱く残す**: ぼかし 48dp→16dp、範囲を下部 25% だけ、濃さ最大 40% にし、遅延なしで最初から表示する。変化は見えなくなるが、負荷は残る。
- 「ぼかしを減らす」設定がオンのときは、すでに2段目が無効。案1なら、この設定による見た目の差もなくなる。
- この処理はアルバム・曲入りフォルダ・プレイリスト・お気に入りの全画面アートで共通なので、1か所の修正で全部に効く。

### 要確認
- E. 案1(ぼかし廃止)でよいか(推奨: 案1)。
