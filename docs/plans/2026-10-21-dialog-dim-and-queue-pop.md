# 全画面ウィンドウの暗さ・キューボタンの処理落ち — Implementation plan

## 症状
1. イコライザーを開くとき、ワンテンポ遅れて見える。閉じるときに、黒みがかった画面が一瞬見える。
2. 再生画面の下の列で、キューボタンを押したときにアイコンの動きが処理落ちっぽくなる。

## 原因

### 1. 全画面ウィンドウの「後ろを暗くする」効果
- イコライザーは、アプリとは別の全画面ウィンドウ(ダイアログ)で開いている(v2.4.0 で下から出るシートから作り替えた)。
- Android のダイアログには、後ろの画面を約 60% 暗くする効果が既定で付く。
- **開くとき**: ウィンドウができた瞬間に後ろが暗くなり、イコライザーは透明から 0.22〜0.32 秒かけて現れる。暗い元の画面が先に見える。
- **閉じるとき**: イコライザーが 0.2〜0.24 秒かけて消える間も暗さは残り、消え終わってからウィンドウが外れて暗さが消える。
- 開いた直後は、上部ボタンの Liquid Glass 用に画面全体の記録も始まっていて、最初の 1 コマが重い。
- 同じ作りの全画面ウィンドウ: タグ編集(2 か所)、歌詞エディター(2 か所)。

### 2. キューボタンの弾みと、キュー画面を作る処理が重なる
- キューボタンを押した瞬間に、キュー画面を一から作る処理(曲の一覧、アートワークの読み込み、今の曲までのスクロール)、アートワークが縮む動き、再生ボタンと音量バーを畳む動きが同時に始まる。
- オンになったときのアイコンの弾みは、一番動く最初の 0.1 秒がこの重い瞬間と重なるため、コマが飛んで見える。
- 歌詞ボタンも、歌詞画面を開く同じ形なので、同じことが起きうる。

## 対応
1. **全画面ウィンドウで後ろを暗くする効果を切る**(5 か所: イコライザー、タグ編集 ×2、歌詞エディター ×2)。
   - 共通の小さな部品 `NoDialogDim()` を作り、各ダイアログの中で呼ぶ。ウィンドウの暗さを 0 にして、暗くする指定を外す。
   - 全画面で後ろを覆う画面なので、暗さはもともと不要。
2. **イコライザーのガラス用の記録を、画面が出きってから始める。**
   - 出入りの動きの間は記録しない。上部ボタンの後ろは無地の背景なので、見た目はほぼ変わらない。
3. **キューと歌詞のボタンでは、オンになったときの弾みをやめる。**
   - 押したときの縮みと、形が丸に変わる動き(0.6 秒)は残す。
   - シャッフル・お気に入り・リピートの動きはそのまま(押しても重い処理が起きない)。

## 対象ファイル
| ファイル | 内容 |
|---|---|
| `ui/components/GlassFloating.kt` | `NoDialogDim()` を追加 |
| `ui/screens/equalizer/EqualizerSheet.kt` | `NoDialogDim()`、ガラス用の記録を出きってから |
| `MainActivity.kt` | タグ編集・歌詞エディターのダイアログに `NoDialogDim()` |
| `ui/screens/LocalMusicScreen.kt` | タグ編集・歌詞エディターのダイアログに `NoDialogDim()` |
| `ui/player/NowPlayingScreen.kt` | キュー・歌詞ボタンの弾みをやめる |

## 今回は対象外
- キュー画面を開く処理そのものを軽くする(前もって作っておくなど)。弾みをやめた後も重さが気になる場合に検討する。

## 確認方法
- イコライザーを開くと、元の画面の上に直接イコライザーが現れ、暗い画面が挟まらないこと。閉じると、元の画面がそのまま見えてくること。
- タグ編集・歌詞エディターを開閉しても、暗い画面が一瞬見えないこと。
- イコライザーの上部ボタンが、開いた後に正しく Liquid Glass で表示されること。
- キュー・歌詞ボタンを押したとき、アイコンがカクつかないこと。形が丸に変わる動きは残っていること。
- ビルドして `release_apk\<version>_<内容>\` に置く。
