## Ch1 文字同期・同期なしの歌詞の見た目を、行同期にそろえる

### 原因

**文字同期の字間が広い**
- `EnhancedLrc.parse`(`data/lyrics/EnhancedLrc.kt:63`)と `TtmlLyrics`(`TtmlLyrics.kt:98, 123`)は、語を `joinToString(" ")` でつないで1行にしています。
- 日本語・中国語では、1文字ずつが1語として届きます(`wordsFromRuns` が、かなと漢字を区切るため)。そのため「君 の 名 前」のように、**すべての文字の間にスペースが入っています。** 字間が広く見えるのはこれです。
- NetEase や QQ 形式(`KaraokeLrc`)は元の文をそのまま使うため、この問題はありません。

**同期なしの歌詞の字形が違う**
- `NowPlayingScreen.kt:4815-4828` で、同期なしの歌詞だけ別の書式を使っています。
  - 同期あり: `headlineLarge`、27sp、行間 33sp、太さは書式どおり
  - 同期なし: `headlineMedium`、23sp、行間 31sp、`SemiBold`
- そのため、大きさと太さが違って見えます。
- 透明度も同期なしは 0.95 で、行同期の「今の行」(1.0)と少し違います。

### 直し方
1. **語のつなぎ方を直す**(`EnhancedLrc` と `TtmlLyrics` の両方)
   - スペースを入れるのは、次のどちらかのときだけにします。
     - 元のデータで、語の間に空白があったとき
     - 前後が両方とも、空白で区切る文字(英字など)のとき
   - かな・漢字・ハングルの前後には入れません。
   - 判定は `SyllableRuns.kt` の `isUnspacedScript()` を使います。
   - 文字の位置を探す `wordSpans` は `indexOf` で探しているので、つなぎ方を変えても位置はずれません。
   - 読み込むときに直すので、**すでに曲ファイルに埋め込んだ歌詞や、保存した .lrc も、そのまま正しく表示されます。**
2. **同期なしの歌詞を行同期と同じ書式にする**
   - 同期なしの書式を、同期ありと同じにします(27sp・行間 33sp・太さも同じ)。
   - 透明度も、行同期の「今の行」と同じ 1.0 にします。
3. 文字同期の語が浮く動き(`riseWith`)は、1文字ずつ少し拡大して描いています。1 を直したあとに実機で見て、それでも字間が広く見えるなら、日本語のときだけ拡大を控えめにします。

**EA: 同期なしの歌詞の大きさ**
- **A【推奨】** 行同期とまったく同じにする(27sp)。
- B 太さだけそろえて、大きさは今の 23sp のままにする。同期なしの歌詞は長いので、一度に見える量を優先する案です。

## Ch2 埋め込み歌詞がない曲は、自分で歌詞を選ぶ(新しい設定)

### 今の動き
- 歌詞は2か所で自動的に探されています。どちらも、埋め込み歌詞が見つからなければネットで探します。
  - プレイヤー: `MainViewModel.loadLyrics`
  - 通知や裏での再生: `PlaybackService.loadLyricsForCurrentTrack`
- さらに「歌詞を自動で埋め込む」(`autoEmbedLyrics`)は最初からオンです。そのため、**自動で見つかった歌詞が、曲ファイルにそのまま書き込まれています。**

### 直し方
- 新しい設定を追加します。名前は「埋め込み歌詞がない曲は自分で選ぶ」で、**最初からオン**です。
  - 内部名は `AppSettings.lyricsManualForLocal`、キーは `KEY_LYRICS_MANUAL_FOR_LOCAL` です。
- 対象はローカルの曲だけです。YouTube の曲は、今までどおり自動で探します(EB)。
- オンのとき:
  - 埋め込み歌詞と、横に置いた .lrc ファイルがあれば、それを使います。
  - どちらもなければ、ネットで探しません。
  - **プレイヤーのミニ歌詞の部分(シークバーの上の1行)を、そのまま「歌詞を選ぶ」ボタンにします。**
    - 今は、歌詞がないと「歌詞はありません」が出るだけで、押しても何も起きません(`NowPlayingScreen.kt:3167` の `LyricsUnavailableLine`)。
    - これを「♪ 歌詞を選ぶ」に変えて、押すと歌詞カタログが開くようにします。見た目は、歌詞があるときの1行と同じ形です。
    - 歌詞パネルの下にある「歌詞を選ぶ」は、今のまま残します。
    - 「歌詞なしの表示を隠す」がオンでも、この1行は出します。これは操作のボタンで、案内の文ではないからです。
    - 「状態の表示を隠す」がオンのときは、出しません。
  - ネットで探さないので、自動で曲ファイルに書き込むこともなくなります。
  - `PlaybackService` 側も同じ条件で止めます。止めないと、通知の歌詞だけが自動で付いてしまいます。
- カタログで「この曲に使う」を選んだ歌詞は、今までどおり優先して使います。
- 設定画面では、「歌詞ソース」の近くに置きます。検索の言葉も登録します。

**EB: 対象の範囲**
- **A【推奨】** ローカルの曲だけ。
- B YouTube の曲も含めてすべて。このとき、YouTube の公式歌詞も出なくなります。

## Ch5 歌詞が進む途中で、少し戻ってから進み直す

### 原因
- 歌詞の時計(`rememberLyricClock`、`NowPlayingScreen.kt:3977`)は、次のように動いています。
  - 再生位置の知らせを受けるたびに、その値に時計を合わせ直します。
  - 知らせと知らせの間は、画面の1コマごとに時計を自分で進めます。
- 再生位置の知らせは 0.5 秒ごとに届きます。ほかの出来事が起きたときにも届きます(`PlayerConnection.kt:223, 267`)。
- この再生位置は、別のプロセスにある再生エンジンからの見積もりです。そのため、コマで進めた時計より、数十〜数百ミリ秒遅れていることがあります。
- 遅れた値に合わせ直すと時計が戻り、白く光っている部分が**少し戻ってから、また進みます。**
- 合わせ直すたびに処理を最初からやり直すので、そのコマが少し引っかかることもあります。

### 直し方
- 時計の処理は、ずっと動かし続けます。再生位置の知らせを受けても、最初からやり直しません。
- 知らせを受けたら、時計とのずれを見て、次のように直します。
  - **ずれが 0.8 秒より大きい**、または一時停止・シーク・曲の切り替えのとき: すぐにその位置へ合わせます。
  - **時計が少し進みすぎているとき**: 戻しません。0.3 秒ほどかけて、時計を少しゆっくり進めて追いつかせます。
  - **時計が少し遅れているとき**: 同じように、少し速く進めて追いつかせます。
- これで、シーク以外では表示が戻らなくなります。
- 確認のときは、ずれの大きさを一時的にログに出して、どれくらい戻っていたかを実機で測ります。測ったら、ログは消します。

## Ch6 設定画面のカテゴリ表示

### 今の作り
- `SettingsScreen` は、1本の長い縦スクロールです。その中に 12 のグループが並んでいます。
  - 再生 / プレーヤー操作ボタン / 歌詞の表示 / 外観 / メインナビゲーションのタブ / パフォーマンス / ローカルの音楽 / ストレージ / プレイリスト / あなたのデータ / 言語 / 詳細オプション
- このうち「外観」は約 1,100 行あります。テーマ、Liquid Glass、プレイヤー画面、歌詞の設定、歌詞ソースまで、すべてが入っています。

### 作るもの
- 「設定を検索」の**すぐ下**に、切り替えスイッチを1行置きます(EF)。
- オンのとき:
  - 設定のカテゴリを一覧で出します。各行に、アイコン、名前、中身の例が出ます。
  - カテゴリを押すと、その設定だけが並ぶページに入ります。
  - 上の「‹ カテゴリ名」か、端末の戻る操作で一覧に戻ります。
  - 一覧に戻ると、スクロール位置も戻ります。
- 検索は、スイッチがオンでもオフでも、すべての設定から探します。
- スイッチの状態は保存します。最初はオフです。

**カテゴリの分け方**(EG【推奨】A)
| カテゴリ | 中身 |
|---|---|
| 再生 | 今の「再生」 |
| プレイヤー画面 | 今の「プレーヤー操作ボタン」と、「外観」の中のプレイヤーの部分(アートワーク、再生ボタンを動かす、大きい画面のプレイヤーなど) |
| 歌詞 | 今の「歌詞の表示」と、「外観」の中の歌詞の部分(同期歌詞、ぼかし、自動埋め込み、厳密さ、歌詞ソース、Ch2 の新しい設定) |
| 見た目 | テーマ、アプリのアイコン、Liquid Glass、ナビゲーションバー、メインナビゲーションのタブ |
| ローカルの音楽 | 今の「ローカルの音楽」と「プレイリスト」 |
| 動作と保存 | パフォーマンス、ストレージ |
| データ | あなたのデータ |
| その他 | 言語、詳細オプション |

- 「外観」は、中で3つのグループ(見た目・プレイヤー画面・歌詞)に分けます。
- スイッチがオフのときも、この分け方で並びます。見出しが少し増えて、探しやすくなります。

### 作り方
- `SettingsCategory` という一覧を作り、今あるグループの前に「このカテゴリを表示中か」の判定を1つずつ足します。
- 1本の画面のまま作るので、今あるたくさんの状態をそのまま使えます。そのため、大きな作り直しはしません。
- 戻る操作は `BackHandler` で受けます。カテゴリのページの中だけで効きます。

**EF: スイッチの名前**
- **A【推奨】** 「カテゴリ別に表示」
- B 「項目ごとにまとめる」
- C 「分類して表示」

**EG: カテゴリの分け方**
- **A【推奨】** 上の表のとおり、「外観」を分ける。
- B 今の 12 グループをそのままカテゴリにする。早く作れますが、「外観」に中身が集まりすぎたままになります。

**EH: 置き場所**
- **A【推奨】** 検索欄の下
- B 検索欄の上

## Ch7 設定の検索欄を Material 3 Expressive にする

- 今は、枠線の入力欄(`OutlinedTextField`)です(`SettingsSheet.kt:1355`)。
- これを丸い検索バーに変えます。
  - 塗りは `surfaceContainerHigh` で、枠線はありません。
  - 高さは 52dp です。
- 押すと、形が変わります。
  - 角が丸から少し締まります(28dp → 16dp)。
  - 塗りが一段明るくなり、アイコンがアクセント色になります。
  - 変わり方はバネの動きで、少しはずみます。
- 入力中は、右に「×」(消す)を出します。

**EI: どの案にするか**(モックを参照してください)
- X1 丸い検索バー
- X2 検索バー＋表示切り替え
- X3 検索バー＋候補チップ
- **【推奨】X2。**
  - Ch6 の「カテゴリ別に表示」を、1行のスイッチではなく検索バーの右の丸ボタンにします。選ぶと、角が締まって色が付きます。
  - 行が1つ減って、検索と表示の切り替えが同じ場所にまとまります。
  - X2 にした場合、EF(スイッチの名前)は、ボタンを長押ししたときの説明と読み上げに使う名前になります。EH(置き場所)は決めなくてよくなります。
