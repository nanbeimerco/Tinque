# 曲送りの滑らかさ・タグの一括編集・歌詞の充実 — 実装計画

2026-11-05

## 要望
1. 曲送り・戻しのアニメーションがガクつく(調査の続き)。曲が切り替わるたびに画面の要素がブレる。
2. タグエディターで、アルバム名やアートワークなどを変えたら、同じフォルダの曲すべてに適用できるオプションがほしい。フォルダタブからも同じことができるようにする。
3. タグエディターまわりのポップアップに、日本語になっていない文章がある。
4. 歌詞を充実させる。
   - プチリリや QQ 音楽など、できるだけ多くの歌詞ソースに対応する。
   - 検索の厳密さを選べるようにする(曲名だけ、曲名＋アーティスト、曲名＋アルバムなど)。
   - 各ソースの歌詞をカタログのように並べ、それぞれの形式(テキストのみ・行ごとに同期・一語ずつ同期)が分かるようにする。
   - 選んだ歌詞を使えるようにし、さらに曲ファイルに埋め込めるようにする。

## Ch1. 曲送りのガクつきの残りと、曲が変わるときのブレ

### 計測で分かったこと
- 曲送りを押すと、プレイヤー画面への知らせが約 0.4 秒のあいだに何度も分かれて届く:曲・再生中か・読み込み中か → 歌詞 → キュー(2〜4 回) → 曲の長さ → アートワークの読み込み など。
- 届くたびにプレイヤー画面全体を作り直し、1 回あたり約 20 ミリ秒かかる。そのあいだコマが落ちる(0.7 秒で 13 コマしか描けない。本来は 84 コマ)。

### 録画で分かったブレ
1. **タイトルの下の行(歌詞・アルバム名の行)が 3 回切り替わる。**
   - 前の曲の歌詞・アルバム名が残る → 「歌詞集を検索中」「言葉を探しています」 → 新しい曲のアルバム名や歌詞。
   - 3 つは文字の太さ・行の高さが違うので、その下の再生時間の行が数ピクセル上下する。
2. **アートワークの大きさが揺れる。**
   - 新しい曲のアートワークを読み込むまで縦横比がいったん正方形に戻り、読み込み後に実際の比率(0.993 などのほぼ正方形)へアニメーションする。
   - アートワークの高さがわずかに伸び縮みし、タイトル以下がまとめて 10 ピクセルほど動く。
3. **文字の変換漏れ。** 「Darlin&apos;Just for me」のように、`'` が `&apos;` のまま出る曲がある。

### 直し方
- **重い更新をまとめる。**
  - 曲送りの直後 0.4 秒は、歌詞とキューの更新を待たせる。三角が流れ終わったら、まとめて 1 回で反映する。
  - 曲・再生状態など、すぐ見せたいものはそのまま。
- **タイトルの下の行。**
  - 曲が変わったら、前の曲の表示はすぐ消す。
  - 読み込み中の表示は、0.5 秒以上かかったときだけ出す。
  - 行の高さを固定して、中身が変わっても下が動かないようにする。
- **アートワーク。**
  - 新しい画像の比率が分かるまでは、今の大きさを保つ。
  - 比率の違いが 2% 未満なら、大きさを変えない。
- **文字の変換。**
  - 歌詞ソースや曲情報から来る文字の `&apos;` `&amp;` `&quot;` `&#39;` などを、表示の前に元の文字に戻す。

### 決めてほしいこと
- **DB: 待たせる時間** → 0.4 秒(三角が流れ終わるまで)。歌詞とキューの表示が最大 0.4 秒遅れて切り替わる。**推奨:0.4 秒。**
- プレイヤー画面を細かく分けて作り直しの範囲そのものを狭くする作業は、今回はしない。上の直しで足りなければ、次の段階で行う。

## Ch2. タグエディター:同じフォルダの曲にまとめて適用

### 今の作り
- タグエディターは 1 曲ずつ。保存すると、その曲の全項目をファイルに書き込む。
- 書き込みの許可は、Android 11 以降なら書き込むファイルごとにシステムの確認を出している。複数のファイルでも 1 回の確認で済ませられる。

### 作るもの
1. **タグエディターに「同じフォルダの曲にも適用」を付ける。**
   - 保存ボタンの上にスイッチを置く。オンにすると、その曲と同じフォルダにある曲すべてに書き込む。
   - 書き込むのは、**この画面で変えた項目だけ。** ほかの曲のタイトルやトラック番号を上書きしないため。
   - スイッチの下に、適用する項目の一覧をチェックボックスで出す(変えた項目に最初からチェック)。外したい項目だけ外せる。
   - タイトル・トラック番号・歌詞は、曲ごとに違うのが普通なので、最初はチェックしない。
   - アートワークを変えた場合は、アートワークもまとめて書き込める。
   - 書き込み前に「12 曲に書き込みます」と確認を出し、終わったら「12 曲中 12 曲に書き込みました」と結果を出す。失敗した曲があれば、曲名を出す。
2. **フォルダタブから一括編集を開けるようにする。**
   - フォルダの ⋮ メニューに「このフォルダのタグをまとめて編集」を追加する。
   - 開くと、フォルダの曲をまとめて編集する画面になる。
     - 全曲で同じ値の項目は、その値を表示する。
     - 曲ごとに違う項目は、「(曲ごとに異なる)」と薄く表示し、触らなければ書き込まない。
   - 書き込みの仕組みは 1. と同じ。
3. **書き込み後。** 書き込んだ曲のライブラリ情報を読み直して、アルバムやアートワークの表示をすぐ新しくする。

### 決めてほしいこと
- **DC: 「同じフォルダ」の範囲** → 案1:そのフォルダの直下の曲だけ。案2:サブフォルダの曲も含める(「Disc 1」「Disc 2」のように分かれたアルバム向け)。**推奨:案1 を基本にし、サブフォルダを含めるスイッチを付ける。**
- **DD: 項目の選び方** → 案1:変えた項目に自動でチェック、外せる(上の案)。案2:チェックなし。変えた項目すべてに必ず適用。**推奨:案1。**

## Ch4. 歌詞:ソースを増やす

### 今の作り
- 歌詞ソースは「拡張機能」として、JavaScript のファイルで書かれている。アプリの中で小さな JavaScript 実行環境(QuickJS)を動かして読み込む。
- 今入っているのは 4 つ:LRCLIB、Apple Music、LyricsPlus、KuGou。
- 拡張機能は `getLyrics`(1 つの答え)と `searchLyrics`(候補の一覧)の 2 つの入口を持てる。
- 新しいソースは、アプリ本体を変えずに拡張機能のファイルを足すだけで増やせる。

### 追加するソースの候補

| ソース | 得意な曲 | 形式 | 備考 |
|---|---|---|---|
| NetEase Cloud Music(網易雲音楽) | 日本のアニメ・J-POP も多い | 行同期、一語ずつ同期 | 検索と歌詞の窓口が公開されていて安定している |
| QQ 音楽 | 中国・日本・韓国 | 行同期、一語ずつ同期 | 一語ずつの歌詞は暗号化されていて、解く処理が要る |
| プチリリ | 日本の曲に強い | 行同期、一語ずつ同期 | 非公式の窓口。仕様が変わると使えなくなることがある |
| Musixmatch | 洋楽全般 | 行同期、一語ずつ同期 | 回数制限が厳しい |
| 歌ネット / J-Lyric / UtaTen | 日本の曲 | テキストのみ(UtaTen はふりがな付き) | 歌詞ページを読み取る方式。ページの作りが変わると壊れる |
| Genius | 洋楽 | テキストのみ | 同上 |

注意:多くは公式に公開された窓口ではなく、利用規約上グレーなものもある。拡張機能として分けておけば、使えなくなったソースは外すだけで済む。

### 決めてほしいこと
- **DE: 追加する順番** → **推奨:**
  - 第 1 弾:NetEase、QQ 音楽、プチリリ(日本の曲の同期歌詞を厚くする)
  - 第 2 弾:Musixmatch、歌ネット、UtaTen、J-Lyric、Genius

## Ch5. 歌詞:検索の厳密さを選べるようにする

### 今の作り:自動で出てくる歌詞の決まり方
1. **曲ファイルに埋め込まれた歌詞**(同じ名前の .lrc を含む)があれば、それを使う。ネットには問い合わせない。
2. なければ、設定で選んだソースだけに、設定の並び順で問い合わせる。
   - 曲名に「Instrumental」などがあれば、歌詞なしとして探さない。
   - 一度見つかった(または見つからなかった)曲は、その結果を覚えておいて使う。
   - 失敗が続いたソースは、しばらく問い合わせない。
3. 同時に 3 つまでのソースに問い合わせる。各ソースには次の順で探してもらう。
   1. 曲名・アーティスト・再生時間(・アルバム)のそのまま
   2. 曲名から「(feat. …)」「[…]」「Official Video」などを外し、アーティスト名も整えて探し直す
   3. アーティストを最初の 1 人(「,」「&」「feat.」より前)だけにして探し直す
4. 決め方:**並び順で上のソースの答えが優先。**
   - 下のソースが先に見つけても、上のソースの答えを最大 3 秒待つ。
   - 3 秒たったら、それまでに見つかった中でいちばん上のソースの答えを使う。
   - 設定「文字同期を優先」がオンのときは、行同期の答えは予備に回し、文字同期の答えが見つかるまで探し続ける。
5. 一致の判断は、ソースごとの作りに任せている(例:LRCLIB は曲名・アーティスト・再生時間で探し、同期歌詞のうち再生時間がいちばん近いものを選ぶ)。アプリ側では一致度を比べていない。

### 今の作り:手で選ぶ入口
- 曲の ⋮ メニュー(一覧・プレイヤーとも)→「歌詞を編集」→ 歌詞エディター →「歌詞を探す」「歌詞をダウンロード」。
- 候補を選ぶと歌詞エディターに入り、「保存」で曲ファイルへの埋め込みか .lrc として保存する。
- 手で探す画面には、曲名・アーティスト・アルバムの入力欄がある。ただし、どれを使って探すかは選べない。
- プレイヤーの歌詞の画面から、直接ほかの候補に切り替える入口はない。

### 作るもの
- 検索画面に「検索に使う情報」を選ぶ欄を付ける。
  - 曲名(必須)
  - アーティスト
  - アルバム
  - 再生時間で絞る(前後 何秒まで、も選べる)
- よく使う組み合わせはボタン 1 つで選べるようにする。
  - **厳密**:曲名＋アーティスト＋アルバム＋再生時間
  - **標準**:曲名＋アーティスト＋再生時間
  - **ゆるい**:曲名＋アーティスト
  - **曲名だけ**
- 結果には「一致度」(曲名・アーティスト・アルバム・時間がどれだけ合っているか)を出し、一致度の高い順に並べる。
- 自動で探すとき(再生中に歌詞を出すとき)の厳密さも、設定で選べるようにする。
- 拡張機能には、どの情報を使うかを渡す。窓口側が対応していない組み合わせ(例:アルバムで探せない)は、取ってきた結果をアプリ側で絞り込む。

- 自動で選ぶときも、アプリ側で一致度を比べるようにする。曲名・アーティスト・アルバム・再生時間の一致度がしきい値に届かない答えは、優先度が高いソースのものでも使わない(関係ない曲の歌詞が出るのを防ぐ)。

### 決めてほしいこと
- **DF: 選び方の見せ方** → 案1:上の 4 段階のボタンだけ。案2:4 段階のボタン＋細かいチェックボックス(上の案)。**推奨:案2。** ボタンで大まかに選び、必要なときだけチェックで細かく変えられる。

## Ch6. 歌詞:カタログ表示と形式の表示

### 作るもの
- 「歌詞を探す」を開くと、全ソースに同時に問い合わせて、届いた順に結果をカード(カタログ)で並べる。
- カード 1 枚 = 1 つの候補。中身:
  - ソース名(NetEase、プチリリ など)
  - 見つかった曲名・アーティスト・アルバム・長さ(今の曲との一致度つき)
  - **形式の表示**(下の DG で名前を決める)
  - 付属情報の表示:翻訳あり / ふりがなあり / コーラス(バックボーカル)あり
  - 歌詞の最初の数行
- カードを押すと、全文をプレビューできる。同期歌詞は、今の再生位置に合わせて動く。
- ソースごとの「探している / 見つからない / 失敗」も、カタログの上に小さく出す。
- 絞り込み:形式で絞る(例:一語ずつ同期だけ)、ソースで絞る。

### 開く入口
- 今の「⋮ →歌詞を編集 →歌詞を探す」に加えて、もっと短い入口を作る。
- **DJ: 入口の場所**
  - 案1:プレイヤーの歌詞の画面で、歌詞のソース名(下に小さく出ている「LRCLIB」など)を押すとカタログが開く。
  - 案2:プレイヤーの ⋮ メニューに「歌詞を選ぶ」を追加する。
  - 案3:案1＋案2 の両方。
  - **推奨:案3。** 歌詞を見ていて「違う」と思ったその場で開け、歌詞を出していないときもメニューから開ける。
- カタログで選んだ歌詞はすぐプレイヤーに出る(Ch7 の「この曲に使う」)。保存や埋め込みは、選んだあとに続けて選べる。

### 決めてほしいこと
- **DG: 形式の表示名**
  - 案1:「テキスト」「行同期」「文字同期」
  - 案2:「歌詞のみ」「行ごと」「一語ずつ」
  - 案3:英語のまま「Plain」「Synced」「Word」
  - **推奨:案1。** 短くて、カードの小さな札にも収まる。付属情報は「翻訳」「ふりがな」「コーラス」の札で並べる。

## Ch7. 歌詞:適用と、ファイルへの埋め込み

### 今の作り
- 歌詞エディターから、歌詞を曲ファイルに埋め込む機能と、同じ名前の .lrc ファイルとして保存する機能がある。
- 再生中は、ファイルに埋め込まれた歌詞 → .lrc → オンラインのソース、の順に探している。

### 作るもの
- カタログのカード(またはプレビュー)から、次の操作を選べるようにする。
  1. **この曲に使う**:Tinque の中だけで、この曲にはこの歌詞を使うと覚える。ファイルは変えない。
  2. **.lrc として保存**:曲と同じ場所に .lrc ファイルを作る。
  3. **曲ファイルに埋め込む**:曲ファイルの歌詞の項目に書き込む。
- 一語ずつ同期の歌詞を保存・埋め込みするときの形式は DH で決める。
- 埋め込むときは、Ch2 と同じ仕組みで書き込みの許可を取る。
- 「この曲に使う」を選んだ曲は、次からはその歌詞をまず使う(ソースを探しに行かない)。いつでも元に戻せる。
- アルバム単位でまとめて歌詞を取ってきて埋め込む機能は、今回はしない(次の段階)。

### 決めてほしいこと
- **DH: 一語ずつ同期の保存形式**
  - 案1:拡張 LRC(行の時刻に加えて、語ごとに `<00:12.34>` を入れる形式)。多くの音楽アプリで、少なくとも行同期として読める。
  - 案2:行同期の LRC に落として保存する(一語ずつの情報は捨てる)。
  - 案3:案1 を標準にして、設定で案2 に切り替えられる。
  - **推奨:案3。**
- **DI: 翻訳・ふりがなの扱い** → **選べるようにする(決定)。**
  - 保存・埋め込みの操作のときに「翻訳を残す」「ふりがなを残す」を選べる。最初はどちらもオフ(本文だけ)。
  - 残す場合、翻訳は本文の各行の直後に同じ時刻の行として入れる(多くのアプリで「訳つき LRC」として読める形)。ふりがなは、漢字の後ろに括弧書き「漢字(かんじ)」で入れる。
  - 翻訳やふりがなを残すと、ほかのアプリでは表示が崩れることがある。選ぶ画面にその注意を一言添える。
  - Tinque 自身は、残した翻訳・ふりがなを読み戻して、今と同じように表示できるようにする。
